# CXBA分析注意事项

本Skill集中维护真实运行中已经暴露并验证过的通用分析错误。它不替代材料类型、统计、图谱、来源对账或Claim专项Skill，只负责在执行前提醒、执行后自检，并把新问题整理成待确认候选。

这些条目是防止已知错误重现的最低护栏，不限制Agent根据当前材料设计新的统计、图、时序、碰撞或核查方法。新方法只要不违反权限、证据、计算和交付合同，并记录输入、参数、结果、失败及限制，就可以使用。

## When to Use

准备执行以下任一动作时加载：读取陌生表格或流水结构；编写或修改来源适配器、临时Python脚本；进行金额、方向、去重、图或图时序计算；把候选升级为证据或最终Claim；复核已有脚本和结果。

普通寒暄、只查看材料名称/数量、只读已确认知识或不涉及材料分析时不加载。

## Prerequisites

- 先确认当前任务和材料范围，不因加载本Skill扩大读取范围。
- 原始材料保持只读；脚本、底稿和结果写入`/workspace`。
- 本Skill提供通用防错规则，真实字段、取值、业务含义和方向仍以当前原件为准。

## How to Run

1. 阅读下方`Verified Pitfalls`，只选择与当前问题相关的条目。
2. 只选择与当前问题相关的条目，写进临时脚本或分析合同的自检项；不要在对话中复述整份规则。
3. 执行脚本后逐项检查覆盖、金额、方向、重复、定位、归因和未知项；失败时修复同一脚本并重跑，不手工补数。
4. 将最终采用的规则和仍未解决的限制记录到分析笔记、问题覆盖矩阵或证据台账。

## Quick Reference

- 候选池可以宽，但不能提前命名为同事、亲属或关联人。
- 负金额、摘要词或Sheet名称不能单独决定收付方向和主体角色。
- 金额使用`Decimal`，不得用`float`形成正式结论。
- 保留原文件、Sheet/页和原始行；排序或重置索引前先保存定位。
- 区分重复文件、镜像观测、重复业务事件、汇总/明细、冲正退款和真实相似交易。
- 身份未知或关系未知的候选不得静默丢弃。

## Procedure

新问题只有满足以下条件才可进入公共规则：真实运行已复现；错误会影响覆盖、计算、方向、去重、证据定位或业务归因；规则可跨案件复用；正确处理已由原件、确定性测试或人工复核确认。

普通调查Run不生成Skill候选文件，也不修改公共Skill。只有SuperAdmin可以从已完成Run发起“维护分析能力”，读取完整Run、脚本、结果和当前Skill，生成完整单文件UPDATE草稿；SuperAdmin查看Diff并确认后，系统同步源码与运行Profile。不得写姓名、企业、账号、证件号、金额、原始流水或材料正文。

确认新规则后，将其归入下方现有主题或新增主题，并增加与风险相称的回归测试。相同问题只维护一条，补充适用范围而不复制同义规则。

## Verified Pitfalls

### AP-001 候选池命名过早

- 错误表现：把全量交易对手候选池直接命名为同事、亲属或关联人。
- 正确处理：候选池允许包含账户、客户号、来源内姓名、企业、银行内部节点和未知观测；先按统计、图和时序信号筛选，再核查身份和关系。
- 自检：输出节点层级和身份/关系解析状态；进入人员主档时另按强标识归并。

### AP-002 Sheet名称冒充交易主体

- 错误表现：直接把人员Sheet名称作为付款人或收款人。
- 正确处理：Sheet名称只说明来源位置或观察视角；主体必须来自原件角色字段和方向规则，字段缺失时保留未知。
- 自检：每条边保存原始角色字段、解释后的收付节点和原始行。

### AP-003 负金额或摘要词直接决定方向

- 错误表现：把负金额直接当入账/出账，或看到收款、汇入、贷记就判断流入。
- 正确处理：结合真实收入/支出列、借贷标志取值、余额变化、成对记录或已验证来源规则确定方向；方向不唯一记`DIRECTION_UNKNOWN`。
- 自检：正式入账不存在负金额；冲突记录全部单列且不进入路径。

### AP-004 使用float计算正式金额

- 错误表现：使用`float`累计、比较或勾稽金额。
- 正确处理：清理经确认的千分位和单位后使用`Decimal`，结果JSON保存十进制字符串。
- 自检：分组金额严格等于总额，原始复算值等于交付物回读值。

### AP-005 把相似交易直接去重

- 错误表现：按姓名、金额、日期接近、相邻行、文件名或相同表头自动去重。
- 正确处理：区分完全相同文件、重复业务事件、收付镜像、汇总/明细、冲正退款和真实相似交易；只有稳定事件键或可核验配对才能自动合并。
- 自检：报告原始观测行数、去重后事件数、镜像合并数和无法确认重复风险的行数。

### AP-006 把冲正或退款当重复删除

- 错误表现：发现反向或负值记录后删除原交易或冲正记录。
- 正确处理：冲正、退款和更正作为关联的新事件保留，分别报告毛额和已知净影响。
- 自检：原事件、反向事件和未匹配记录数量守恒。

### AP-007 缺少原始行号

- 错误表现：脚本只输出汇总或重置后的DataFrame索引。
- 正确处理：读取时保存原文件、Sheet/表、原始行或唯一流水；排序、过滤、合并和重置索引后继续携带。
- 自检：每个候选和计算输入均能回到参与计算的真实记录。

### AP-008 第一个命中后提前返回

- 错误表现：匹配函数找到第一个人员或交易后`return`。
- 正确处理：遍历全部事件和候选；只在结束内层匹配时使用`break`并继续下一事件。
- 自检：处理行数与输入一致，改变排序不改变候选集合。

### AP-009 客户资料代替交易明细

- 错误表现：只读开户或客户资料就声称完成资金分析。
- 正确处理：客户/开户资料用于身份和账户映射，交易明细用于事件和路径，两者分别记录覆盖和缺口。
- 自检：每项资金结论都引用真实交易明细。

### AP-010 身份未知候选被过滤

- 错误表现：交易对手身份或关系未知就从统计和图路径中删除。
- 正确处理：使用账户级、来源内姓名级或观测级节点继续分析，查不到身份时以`HYPOTHESIS`或`GAP`输出事实、定位和调证动作。
- 自检：报告身份/关系已知与未知候选数量，未知候选可追踪。

### AP-011 反证使原疑点静默消失

- 错误表现：找到正常解释、退款、冲正或其他反证后删除原疑点。
- 正确处理：无充分反证的候选进入待核疑点；有反证的候选连同触发事实进入暂拟排除的疑点，写明重新打开条件。
- 自检：算法候选、证据台账和报告可对账，反证使用`COUNTER`来源而不覆盖支持证据。

### AP-012 把有界口径外推成整体结论

- 错误表现：只检查一个资金方向、一个金额阈值、一个目标账户、一个人员名单或一种业务角色后，把零命中或未见异常表述成“整体没有问题”；或者用“申请人”排名代替“收款人”排名。
- 正确处理：每个结果明确方向、阈值、端点、主体角色、期间和实际来源，只回答该口径。用户要求整体分析时，分别覆盖有业务意义的正反方向、申请人与收款方、直接与间接路径，并先做不设主观金额阈值的分布与排名；当前材料无法覆盖的维度写成`GAP`。
- 自检：最终回答能逐项区分“本口径零命中”“尚未检查”“材料不能判断”和“有反证暂拟排除”，不把任何一项改写为整体不存在。

## Pitfalls

- 不把一次案件中的偶发现象泛化为所有银行、文件或业务系统的规则。
- 不把具体模板的字段值写成无条件通用含义；必须保留“以当前原件核验”的边界。
- 不把办案知识中的新型数据源、技战法或本案疑点复制进本技术Skill。
- 不因规则库增长而每次全文转述；读取后只应用相关条目。

## Verification

- 当前脚本能说明采用了哪些避坑条目及其真实字段依据。
- 输入行、接受行、排除行、未知行和去重后事件数量守恒。
- 所有金额、方向、重复合并、主体归因和原始定位均可回查。
- 新增规则已脱敏、可复现、可跨案件复用，并经SuperAdmin确认后才进入公共Skill。
